# TaskManager 同步验收清单

仓库：`smileQiny/taskmanager` · 建议在 **桌面版**（`npm run tauri dev` 或已安装的 App）上测。浏览器 `npm run dev` 只能点 UI，连接会明确提示「不能连接」，且不会显示为成功。

通用约定：

- 设置页路径：**设置 → 远端同步**
- 任务侧勾选：打开任务详情 → **远端同步** 里对应平台开关
- 同步状态文案：`待同步` / `需授权` / `已同步` / `冲突` / `错误`
- 冲突按钮：**保留本地** / **采用 Google|飞书|企业微信|日历**
- 当前 **不支持** 重复规则（recurrence）的设置与同步
- 未勾选同步的任务，远端不应出现对应事件

每项通过打 `[x]`，失败在右侧记下报错原文。

---

## 0. 环境与冒烟（先做一次）

- [ ] 用桌面版打开应用（不是纯浏览器预览）
- [ ] **设置 → 本地数据** 能看到数据目录与数据库路径
- [ ] 新建一条带开始/结束时间的任务，保存后能在「今日 / 任务 / 日历」看到
- [ ] 删掉测试任务后列表不再残留

## 1. Google Calendar

### 1.1 准备（控制台）

- [ ] 已启用 Google Calendar API
- [ ] OAuth 同意屏幕已加测试用户（你的 Google 账号）
- [ ] 已创建 **Desktop** 类型 OAuth Client，拿到 Client ID（Secret 可选）
- [ ] Scope 含 `https://www.googleapis.com/auth/calendar.events`

### 1.2 连接

- [ ] 设置里打开 **Google Calendar** 启用开关
- [ ] 填入 Client ID、日历 ID（`primary` 或具体日历 ID）→ 保存
- [ ] 点 **连接 Google** → 系统浏览器完成授权 → 回到应用显示已连接
- [ ] 故意填错 Client ID 再连 → 有明确错误，不能假成功
- [ ] 点 **断开** → 状态变为未连接；再连可恢复

### 1.3 任务同步（本地 → Google）

准备：新建任务 A（标题含 `G-A`、有起止时间），详情里勾选 **Google**。

- [ ] 状态先为 `待同步` 或类似等待态
- [ ] 设置里点 **立即同步** → 任务变 `已同步`
- [ ] Google Calendar 出现同名事件，时间一致（注意时区）
- [ ] 改任务标题/时间并保存 → 再同步 → Google 侧更新
- [ ] 新建全天任务 B，勾选 Google → 同步 → Google 为全天事件，日期正确

### 1.4 远端 → 本地

- [ ] 在 Google 里只改事件 A 的标题或时间 → 回应用 **立即同步** → 本地任务跟上
- [ ] 本地与 Google **两边都改** 同一任务后同步 → 状态变 `冲突`，两边都未被静默覆盖
- [ ] 点 **保留本地** → 再同步 → Google 被本地内容覆盖，冲突消失
- [ ] 再制造一次冲突 → 点 **采用 Google** → 本地被远端覆盖，冲突消失

### 1.5 边界

- [ ] 未勾选 Google 的任务，同步后 Google 不新增事件
- [ ] 删除已同步任务 → mapping 不残留脏数据（再同步不复现幽灵事件）；Google 侧是否删除以当前实现为准，记下实际行为
- [ ] 取消勾选 Google → 再同步不应对该任务继续推送新变更（记下实际行为）

## 2. 飞书 / Lark 日历

### 2.1 准备（开放平台）

- [ ] 企业自建应用；记下 App ID / App Secret
- [ ] 权限（用户身份）已开并发布版本：`offline_access`、`calendar:calendar:readonly`、`calendar:calendar.event:read|create|update`
- [ ] 安全设置回调地址**精确**为：

  ```text
  http://127.0.0.1:43821/callback
  ```

  （不要用 `localhost`；需要时打开刷新 `user_access_token` 并再发布）
- [ ] 应用对测试账号可用

### 2.2 连接

- [ ] 设置选域名：**飞书（open.feishu.cn）** 或 **Lark（open.larksuite.com）**
- [ ] 填 App ID、App Secret、日历 ID（`primary` 或具体 ID）→ 保存
- [ ] 点 **连接飞书** → 浏览器授权 → 回环成功 → 应用显示已连接
- [ ] 故意用错回调或 Secret → 有明确失败，不显示成功
- [ ] **断开** 后再连可恢复

### 2.3 任务同步

准备：任务 F（标题含 `F-A`），详情勾选 **飞书**。

- [ ] **立即同步** → `已同步`；飞书/Lark 日历出现对应事件
- [ ] 只改本地再同步 → 远端更新
- [ ] 只改远端再同步 → 本地更新（飞书无服务端更新时间戳，靠内容指纹）
- [ ] 双边都改 → `冲突` → **保留本地** / **采用飞书** 各测一次，结果符合所选
- [ ] 全天任务日期正确（飞书侧结束日为排他 UTC 日的行为与 README 一致即可）
- [ ] 未授权时任务状态可为 `需授权`；详情提示去设置连接

### 2.4 浏览器预览负向

- [ ] 纯浏览器打开时提示「浏览器预览不能连接飞书…」，且不把同步标成成功

## 3. 企业微信

### 3.1 准备（管理后台）

- [ ] 自建应用：CorpID、AgentId、Secret
- [ ] 可见范围含目标成员；记下该成员 **userid**
- [ ] **协作 → 日程** 把本应用加入「可调用接口的应用」并保存/发布
- [ ] 应用 **企业可信 IP** = 本机当前公网 IP（改完等约 1 分钟）
- [ ] 知悉限制：只能读写**本应用创建的日历**上的日程；标题 ≤128、描述 ≤1000

### 3.2 连接

- [ ] 设置填 CorpID、AgentId、Secret、成员 userid
- [ ] 日历 ID 留空/`primary` → 点 **连接企业微信** → 应创建 Task Manager 日历并共享给该成员
- [ ] 或填已有本应用 `cal_id` → 连接成功
- [ ] IP 未加白或 Secret 错误 → 明确报错
- [ ] **断开** 后 access token 清除；Secret 仍留在本机直至清空字段（与 README 一致）

### 3.3 任务同步

准备：任务 W（标题含 `W-A`），详情勾选 **企业微信**。

- [ ] **立即同步** → `已同步`；企业微信日历出现日程，该成员可见
- [ ] 只改本地 / 只改远端 / 双边冲突 → 行为同飞书（指纹 + **保留本地** / **采用企业微信**）
- [ ] 全天任务：结束落在本地午夜（整点时区偏移限制可接受）
- [ ] 超长标题/描述 → 有合理截断或错误提示，不静默丢数据到不可用状态
- [ ] 描述里不应长期露出原始 `[taskmanager:…]` 标记给用户（写回本地前应剥掉）

### 3.4 负向

- [ ] 浏览器预览明确拒绝连接，不标成功
- [ ] 尝试同步「非本应用日历」上的个人日程 → 失败或不可见，符合 API 限制

## 4. macOS 日历

仅在 **macOS** 桌面版测。

### 4.1 权限与连接

- [ ] 设置启用 **macOS 日历**
- [ ] 按提示请求 **完整日历访问**；系统设置里权限为允许
- [ ] 日历列表可刷新；能选目标日历（或默认日历）并保存
- [ ] 非 macOS 构建上显示「仅 macOS / 不会执行同步」类提示

### 4.2 任务同步

准备：任务 M（标题含 `M-A`），详情勾选 **macOS**。

- [ ] **立即同步** → `已同步`；「日历」App 出现事件
- [ ] 只改本地 / 只改「日历」App / 双边冲突 → `冲突` 与 **保留本地** / **采用日历** 正确
- [ ] 全天任务在「日历」里日期正确
- [ ] 拒绝权限后：任务可为 `需授权`；同步失败有可读错误

## 5. 交叉与回归

- [ ] 同一任务可同时勾选多个 provider（若你需要多端）→ 各点一次同步，两端都出现事件且互不串日历
- [ ] 设置页顶部「上次同步」摘要：`provider · status`、message、影响任务数与刚测结果一致
- [ ] 主题 / 默认日历视图切换仍正常（同步改动不应破坏设置）
- [ ] 断网时同步 → 明确失败，不把任务标成已同步
- [ ] 重启应用后：各平台连接态、已同步 mapping 仍在（token 在钥匙串或加密表）
